# Data Model: Research Retrieval and RAG Context

**Feature**: `036-research-retrieval-rag`
**Migration**: `M009_ResearchRetrieval` on `ResearchDbContext` schema `research`

## New Tables

### `research_documents`

Parent record for every indexed research object.

| Column | Type | Notes |
|---|---|---|
| `Id` | uuid PK | Generated by application |
| `SourceType` | varchar(40) | `NewsArticle`, `InvestmentThesis`, `DecisionNote`, `ThesisEvent`, `Postmortem`, `FilingExcerpt`, future-safe |
| `SourceId` | varchar(80) | Original entity id or stable external id |
| `UserId` | uuid NULL | NULL means global research document; non-null means private to user |
| `Title` | varchar(500) | Required |
| `CanonicalUrl` | text NULL | External source URL when available |
| `SourceName` | varchar(160) NULL | Feed/provider/source display name |
| `PublishedAt` | timestamptz NULL | External publication time |
| `CapturedAt` | timestamptz | Time Finance Sentry stored it |
| `ContentHash` | varchar(128) | Hash of normalized text + important metadata |
| `Text` | text | Normalized retrievable text |
| `Tickers` | jsonb | `List<string>`, normalized uppercase |
| `ThesisIds` | jsonb | `List<Guid>` |
| `IndexStatus` | varchar(30) | `Pending`, `Indexed`, `Failed`, `Skipped` |
| `IndexFailureReason` | text NULL | Last failure reason |
| `IndexedAt` | timestamptz NULL | Last successful indexing time |

**Indexes**:

- Unique `(SourceType, SourceId, UserId)` for source identity.
- `(IndexStatus, CapturedAt)` for indexing work selection.
- GIN indexes for `Tickers` and `ThesisIds` if supported cleanly by the existing EF/Postgres setup.
- `(PublishedAt desc)` for freshness filters.

### `research_chunks`

Deterministic retrieval units derived from documents.

| Column | Type | Notes |
|---|---|---|
| `Id` | uuid PK | Generated by application |
| `DocumentId` | uuid FK | `research_documents.Id`, cascade delete |
| `Ordinal` | int | Stable order within document |
| `Text` | text | Chunk text |
| `ContentHash` | varchar(128) | Hash of normalized chunk text |
| `TokenEstimate` | int | Approximate token count |
| `StartOffset` | int NULL | Character offset when available |
| `EndOffset` | int NULL | Character offset when available |
| `CreatedAt` | timestamptz | |

**Indexes**:

- Unique `(DocumentId, Ordinal, ContentHash)` for idempotency.
- Full-text/lexical index over `Text` if supported by the chosen implementation.

### `research_embeddings`

Vector representation of chunks.

| Column | Type | Notes |
|---|---|---|
| `Id` | uuid PK | Generated by application |
| `ChunkId` | uuid FK | `research_chunks.Id`, cascade delete |
| `Provider` | varchar(60) | e.g. configured provider key |
| `Model` | varchar(120) | configured model name |
| `Dimensions` | int | vector length |
| `EmbeddingVersion` | int | increments when chunking/model rules change |
| `Vector` | vector or provider-compatible storage | Preferred: pgvector |
| `CreatedAt` | timestamptz | |

**Indexes**:

- Unique `(ChunkId, Provider, Model, EmbeddingVersion)`.
- Vector similarity index appropriate to configured dimensions and pgvector operator class.

### `research_retrieval_audit`

Optional but recommended audit table for MCP retrieval calls.

| Column | Type | Notes |

| `Query` | text | truncated if needed |

| `ResultCount` | int | |
| `CreatedAt` | timestamptz | |

## Derived DTOs

### `ResearchSearchResult`

- `query`
- `results[]`
- `retrievedAt`

Each result includes:

- `documentId`
- `chunkId`
- `sourceType`
- `sourceName`
- `title`
- `canonicalUrl`
- `publishedAt`
- `capturedAt`
- `tickers`
- `thesisIds`
- `snippet`
- `semanticScore`
- `lexicalScore`
- `combinedScore`

### `ResearchContextPacket`

- `subjectType`: `Thesis` or `Ticker`
- `subjectId`
- `ticker`
- `thesis`
- `groups[]`
- `omittedCount`
- `retrievedAt`

Groups should be stable enough for Ledger to reason predictably:

- `thesis`
- `decision_notes`
- `recent_news`
- `filings`
- `postmortems`
- `other_research`

## State Transitions

- `Pending` -> `Indexed`: chunks and active embeddings were created.
- `Pending` -> `Skipped`: no usable text or unsupported source type.
- `Pending` -> `Failed`: retryable indexing or embedding failure.
- `Failed` -> `Indexed`: later retry succeeds.
- `Indexed` -> `Pending`: source content hash changes or embedding version changes.
